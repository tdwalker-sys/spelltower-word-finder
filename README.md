# SpellTower Word Finder

Standalone copy of the SpellTower Word Finder, converted from the Claude artifact on 2026-10-01. It runs entirely in the browser and needs no Claude account.

## What changed from the artifact

- The "Read with Claude" photo reader is removed. "Read a screenshot" (the built-in text reader) is unchanged.
- The two fonts are bundled in `fonts/` instead of loading from Google.
- `manifest.webmanifest`, `sw.js` and `icons/` make it installable and usable offline.
- "Letters only" (added 2026-10-09): type a handful of letters, in any order, and get every word that can be spelled from them without entering the board. `?` is a wild tile. Optional "starts with", "ends with" and "contains" fields narrow the list (each can be several letters; "contains" is a run of letters anywhere in the word, added 2026-10-12). Scores are letter values times length, with no board bonuses. The status line also says whether the letters you typed are themselves a word.
- Definitions (added 2026-10-12): tap a word in the "Letters only" results, or the "Define" button next to "Play this word" for a board word, and its Wiktionary senses appear in a panel. Inflected forms ("plural of zoea") are followed to the base word. This is the one feature that needs an internet connection; on a Mac the panel also links to the built-in Dictionary app, which works offline.

- "Add row" button (added 2026-10-09): type a row the game added outside the usual after-each-word prompt, or catch the finder up when it has fallen behind the game. (Corrected 2026-10-10: Zen adds a row after every word just like Puzzle, only without minimum-length tiles, so the "new row after each word" box stays ticked for Zen. Untick it for Tower and Search, which never add rows.)
- "Typed word" (added 2026-10-09): for a word the game accepted but the finder did not list (ENABLE lacks it; JAIN was the first). Type it, it is traced on the board and outlined like any result, "Other path" cycles through tracings that remove different tiles, then "Play this word" removes it as usual. The word is also added to the dictionary and kept in this browser's storage (`st-words`), so it is found from then on.
- "What the reader saw" (added 2026-10-09): after a screenshot is read, the board area of the screenshot is shown with the detected grid drawn in orange, so a missed row or a wrong column count is visible before you trust the letters.

- Reliability round (2026-10-10), after a code review:
  - Any change to the board (tile edit, resize, clear, typed board, new row, screenshot, play, undo) now discards every stored result and typed-word tracing, so an old outline can never remove tiles that have since moved. A tile edit clears the list and says so; Done (or Enter/Escape in the editor) re-runs the search.
  - "Typed word" obeys numbered tiles: a tile marked 6 is not offered in a 4-letter tracing, the same rule the solver applies.
  - "Sort" option: longest first (grouped by length, as before), highest score, or most tiles removed. The solver keeps two tracings per word, the best-scoring and the most-removing, and the sort picks the matching one; the "most tiles removed" view shows the tile count on each word. The choice is remembered.
  - "Letters only" needs as many letters as the minimum length, and a `?` wild counts toward it (`A??` is accepted).
  - "Add row" refuses a row when the board is already 16 tall with tiles in the top row, and says so, instead of growing past what the Rows control allows or silently dropping tiles.
  - Legend wording fixed: yellow tiles are ×2 for one, ×3 for two (what the code always did), not "doubled for each".
  - Tile buttons now read their letter and flags to a screen reader.
  - Screenshot reader: blue row-clear tiles were read as empty on a nearly full board. The screenshots carry Apple's Display P3 profile, and the browser converts them to sRGB when drawing to the canvas, which pushes the tile's red channel to about 115, below the old rule's floor of 130; the other blue rule compared against the "background", which on a full board is the white tiles. The blue rule is now hue-based (blue strongest, red weakest, no background term). Verified on three 2026-10-10 game screenshots (9 columns; 3 blue tiles, 1 blue tile, none).

- Search mode star tile (added 2026-10-11): in Search mode every word must pass through the tile drawn with a grey star behind its letter. The screenshot reader detects that star (flat light grey on the white tile), the tile editor has a "★ star" checkbox, and a typed board marks it with `@` after the letter (`P@`). While any star tile is on the board, the finder lists only words with a tracing through it; a tracing that misses the star is discarded before the best tracing is picked, so a listed word is always shown with a tracing the game will accept. "Typed word" obeys the same rule. Tiles in Search do not disappear, so do not tap Play there; untick "New row after each word" as for Tower. In Search the yellow tiles are worth more points, as elsewhere, so the reader's bonus marking and the ★ tag on words apply. The "★: 7 | ★★: 9 | ★★★: 12" line above the game board is the anchor for word values: each counter is the threshold a word must reach to earn that many stars (reported 2026-10-11; whether the numbers are word lengths or point values is not yet pinned down, so the finder does not show star ratings yet).
- Tower mode (checked 2026-10-11): there is no Tower switch; untick "New row after each word" and read the screenshot. Two reader fixes came out of the first Tower screenshot (9 columns by 13 rows on the gold backdrop). The gold backdrop (about 232,192,88) used to pass the yellow-tile colour test, so the board's left edge landed on the backdrop and every column shifted; the yellow test now needs the tile's brighter green (about 248,224,112), and any pixel close to the screenshot's dominant colour is treated as backdrop unless that colour is white. Separately, thin-stroked letters at small sizes came back as near misses with low confidence (H as L, F as E); a letter read with confidence under 75 is now re-read with thickened strokes and the more confident read wins. Result on that screenshot: 117 of 117 tiles. Verified on an 871-pixel-wide crop, so a full-size screenshot should do at least as well.
- Dark theme (reader support added 2026-10-18; before that it reported "No board found" and the light theme was required): the game's dark look has charcoal tiles (about 35,35,35) with light letters (about 224), blocked tiles only a little darker than the tiles (about 21), blue (about 76,127,162) and gold (about 195,163,74) tiles with the same light letters, on an olive backdrop. The reader now repaints such a screenshot in the light palette before reading it (surface and ink swap, blocked tiles stay black, blue and gold become the light theme's blue and yellow, everything else becomes a flat mid grey), so the rest of the pipeline is unchanged. A screenshot counts as dark when charcoal covers a fifth or more of it and white under a twelfth. Two edge-search fixes came with it: a candidate bottom edge must have a wide band of tile surface just above it (a thin dark strip at the screenshot's bottom edge used to repaint to a white line and crash the reader), and the column test's walk up to the top of the board now stops at a gap of a tenth of the board width instead of a fifth, so the header bar and a notification toast above the board (white with black text once repainted) no longer count as letter ink on the grid lines. The status line says "dark theme" when the repaint was used. Verified in headless Chrome on one dark Tower screenshot (9 columns by 13 rows, 112 of 112 tiles including the blocked, blue and gold cells) and, for no regression, on four light screenshots from 2026-10-11 and 2026-10-18, which read identically before and after. Only Tower's olive backdrop has been seen in the dark theme; a dark-theme mode with a neutral dark grey backdrop could confuse the repaint and has not been checked. The Search-mode star has not been seen in the dark theme either.
- Hosted for the iPad (2026-10-17): the folder is served by GitHub Pages at https://tdwalker-sys.github.io/spelltower-word-finder/ (the repo became public for that; it holds nothing but the files listed here). Same round, for iPad use: autocorrect is turned off on every letter field and the board text box; a screenshot can be pasted or dropped onto the page as well as picked from Photos (only an image is taken, text paste is untouched); a line under the legend reports "Ready for offline use" once the worker has stored every file, or says so if the download failed (before this, a failure was silent); empty-cell hover highlight only on devices with a pointer; the page asks search engines not to index it. Definitions: a Wiktionary server error now reads "Lookup temporarily unavailable" and is not remembered for the session (it used to be cached as "not in Wiktionary"), and the part-of-speech text from Wiktionary is inserted as text, not HTML. Verified the same day in headless Chrome, locally and against the live address, including a reload with the host unreachable (served entirely from the stored files). Still open: the first real run on the iPad (Ready line, Add to Home Screen, Airplane Mode relaunch, screenshot from Photos, paste and Split View drag), 2026-10-17 evening.
- Tile filter and blue-tile sparing (2026-10-18):
  - "Words through this tile": tap a tile, then the new button in the tile editor. The list keeps only words with a tracing through that tile (one tile, not every tile with that letter), the tile gets a blue ring, the status line says "N words found through G (row 3, col 3)", and a "Show all words" button clears it. The filter is applied inside the solver before the best tracing per word is chosen, the same way the Search ★ tile is, so a word that reaches the tile only by a lower-scoring path is still listed, with that path. Any board change drops the filter, since the tile may have moved.
  - "Spare blue tiles" checkbox (remembered): for Tower, where the blue tiles are the way to clear the board. While ticked, each word is shown with a tracing that removes no blue tile where one exists, even if a blue tracing would score more; words that cannot avoid removing one are moved to a trailing group "Would remove a blue tile" rather than hidden. "Removing" counts all three ways a blue tile can go: it is in the word, it sits above/below/left/right of a 5+ letter word, or it is in a row another blue tile (or J, Q, X, Z) clears. Every word that removes blue tiles carries a "−N blue" tag whether or not the box is ticked, the status line counts the blue tiles on the board, and the play panel warns before Play ("This removes 1 blue tile beside the word, the last on the board."). "Typed word" offers the blue-sparing tracing first while the box is ticked. The two features combine.
  - Verified in headless Chrome on a typed 5-column Tower board (34 checks): SAG, which has a blue tracing scoring more than its plain one, switches tracings with the box; RAISE, which only touches the blue tile as an edge neighbour, is tagged and moved to the trailing group; the full word set is identical with the box on and off; every word listed under the tile filter outlines through that tile; the filter survives the spare toggle and clears on a tile edit.
- Tile filter takes several tiles (2026-10-22): "Words through this tile" now adds the tapped tile to the filter instead of replacing the one before; on a tile already in the filter the button reads "Drop this tile from the filter". With two or more tiles the filter panel offers "every one of them" (default) or "any of them"; every ringed tile is listed in the panel and the status line ("23 words found through R (row 2, col 1) and T (row 3, col 2)", or "… or …" under "any"). Use: in Tower, select the tiles you want gone and the list holds only words that take all of them; in Search, select the ★ tile and the yellow tiles you want to reach (the ★ tile is enforced anyway, so selecting it is a reminder, not a change). Same round, the yellow tag on a word changed from ★ to the multiplier it earns (×2 for one yellow tile in the word, ×3 for two), because in Search every listed word already goes through the star tile and the ★ tag read as "through the star" rather than "doubled"; the legend says the same. The yellow multiplier itself is unchanged and was already applied in Search (logged 2026-10-11 above). Verified in headless Chrome on a typed 8-column, 3-row Search board with a star P and a yellow R: 148 words all through P; 69 through R as well; 23 through R and T under "every", 103 under "any"; SPACERS carries 266 and ×2; dropping R leaves 57 through T; "Show all words" and a tile edit both clear the rings and the panel. Not built that round: any look-ahead for Search; whether tiles vanish after a Search word was still unconfirmed, and the legend still said not to tap Play there.
- Search setup words and look-ahead (2026-10-23): two reviews of the 2020 SpellTower+ release (iMore, MacStories, read by a reviewer she pasted, not by me) describe non-star words as legal Search moves that prepare a better scoring word, which matches her own account of spending words to reach yellow tiles. The finder no longer hides them. With a ★ tile on the board the list has scoring words first (through the ★, scored as before, ×2/×3 tags), then "Setup words (no ★ in the word; no score shown)" tagged `setup` with no score, then "Setup words that would remove the ★ tile" last, tagged `removes ★`, for words whose every tracing takes the ★ out without using it (a 5+ letter word's edge neighbour, or a row clear). Tracings are ranked before score, ★-removal worst, then blue-removal when "Spare blue tiles" is on, so a word is shown with a tracing that keeps the ★ whenever one exists. Tapping a setup word runs a one-step look-ahead for that tracing only: the play panel says "After this path, the best ★ word on the next board is REPOTS (156). Another tracing of CATS could leave a different board", or that no ★ word remains, or that the ★ is gone. "Typed word" traces a setup word instead of rejecting it, ★ tracings first. Status reads "148 words through the ★ tile, 118 setup words without it". Setup words show no score rather than "0" because what a setup word earns in the game is unverified. Still unverified, and said so in the legend: whether the ★ stays with its letter when tiles drop (the finder assumes it does), and what the game does when a setup word removes the ★; the reviews cover the 2020 edition, not Apple Arcade's, so the replayable Search tutorial and a before/after screenshot of one setup move are the sources to settle both. ## Rules the simulator uses

The target is the SpellTower (formerly SpellTower+) app, not Puzzmo's version. Words run through adjacent tiles including diagonals. A word of 5+ letters also clears the tiles that share an edge with any of its letters: up, down, left, right, **not diagonals**. That was confirmed 2026-10-10 from a real Zen move (MOUNTAINEERS on a 9-column board): all 18 edge-neighbours went, all 7 corner-only neighbours stayed, including a black tile. The earlier eight-direction rule, taken from Wikipedia and Puzzmo write-ups, is wrong for the app. J, Q, X, Z and blue tiles clear their whole row, and the code includes black tiles in that row clear. Scores are letter values of every tile removed, times word length, times (1 + number of yellow bonus tiles in the word), which is the Puzzmo star-tile formula; the app's own version notes give the base formula as letter values plus bonus letter values times word length, so only the yellow multiplier rests on Puzzmo alone. Yellow tiles are detected by the screenshot reader, set with the "yellow bonus" checkbox in the tile editor, or typed as `!` after the letter (`R!`); words that use one show a ★ in the results.

Open questions to settle in the app before touching the clearing code (noted 2026-10-10):

- **Black tiles beside short words.** Early reviews of the original app say a black tile disappears when any word is made next to it; the finder only removes it through a 5+ letter word's edge-adjacency or a row clear. Check: play a 3-letter word beside a black tile and see whether it goes. (A black tile edge-adjacent to a 5+ letter word is also untested; the 10-10 move only had one at a corner, which stayed.)
- **Letter values.** The app scored MOUNTAINEERS at 744; the finder's table gives 780 (65 points of tiles × 12). The formula shape is right, so a few letter values in `VALUES` are probably off. Needs a few more scored moves to pin down.
- **Row-clear letters.** The code treats J, Q, X, Z as row-clearing even when the tile is not drawn blue, on typed and screenshot boards alike. Puzzmo's newspaper instructions list J, Q, X, V; a review of the original app and a Puzzmo player's examples (CUZ, QUA, WAX, JIG) support Z. Check in the app whether a Z tile is drawn blue. (First evidence 2026-10-10: the Z in a freshly added Zen row was drawn blue, so Z is row-clearing in the app.)
- **Black tiles in a row clear.** Unverified either way.

A screenshot of the app's help screen on tile removal would settle most of these at once.

## Running it

The folder has to be served over http(s); opening `index.html` by double-click will not load the word list or the text reader.

**iPad and iPhone.** Open https://tdwalker-sys.github.io/spelltower-word-finder/ in Safari and wait for the line under the legend to read "Ready for offline use" (about 27 MB downloads the first time). Then Share → Add to Home Screen. From the Home Screen icon it opens as its own app and works without a connection; only "Define" needs internet. To read a board: take a screenshot of the game, open the finder, tap "Read a screenshot" and pick the screenshot from Photos (the dependable route). Two shortcuts also work: copy the screenshot thumbnail and paste into the finder, or in Split View drag the screenshot from Photos onto the page. Words remembered on one device ("Typed word") stay in that device's browser storage; the Mac's local copy and the hosted copy do not share them, so retype a missing word once on each.

**On this Mac.** Double-click `Start Word Finder.command`. It starts a small local server for this folder (only reachable from this Mac) and opens http://127.0.0.1:8765/ in the default browser. The server keeps running until the Mac restarts. The hosted address works on the Mac too.

**Deploying.** The site is the `main` branch of the GitHub repo `tdwalker-sys/spelltower-word-finder`, served by GitHub Pages from the repo root (`.nojekyll` keeps Pages from processing the files). `git push` publishes; the site is live about a minute later, and each device picks up the new `index.html` the next time it is opened online.

## Updating

- A change to `index.html` reaches each device the next time the app is opened online.
- A change to any other file needs the `VERSION` line at the top of `sw.js` bumped (`v1` → `v2`), or devices keep their stored copies.
- The icon is drawn by `icons/icon-source.html`; the PNGs are 512, 192 and 180 pixel renders of it.

## Bundled pieces

- `enable1.txt`: the ENABLE word list (public domain).
- `ocr/`: Tesseract.js and its English model (Apache 2.0).
- `fonts/`: Jost and Source Sans 3 (SIL Open Font License).
